# Agent Tabs: ответвление разговора и откат кода от сообщения

Дата: 2026-11-04. Статус: утверждено в чате (2026-11-04).
Образец поведения: меню у сообщения в Claude Code («Fork conversation from here», «Rewind code to here», «Fork conversation and rewind code»). Код, иконки и тексты Claude Code не копируются.

## 1. Зачем

Агент ушёл не туда, или хочется попробовать другой путь от того же места. Сейчас это делается вручную: новая вкладка, копирование сообщения, ручной откат файлов через git. Нужно в два клика вернуть разговор, код или и то и другое к выбранному своему сообщению, не потеряв исходную ветку.

## 2. Что видит пользователь

- При наведении на своё (пользовательское) сообщение в ленте рядом со временем появляется кнопка ↺ (своя иконка). Клик открывает меню из трёх пунктов:
  1. **«Ответвить разговор отсюда»**: открывается **новая вкладка** с сессией, где история идёт до этого сообщения (само сообщение не входит). Его текст стоит в поле ввода: можно поправить и отправить. Исходная вкладка и её разговор не меняются.
  2. **«Откатить код сюда»**: разговор не меняется. Файлы, которые агент менял **своими инструментами правки** начиная с этого сообщения, возвращаются к состоянию на момент перед ним; файлы, которые агент своими инструментами создал, удаляются. Ручные правки пользователя в других файлах и последствия shell-команд не трогаются.
  3. **«Ответвить и откатить код»**: пункт 1, затем пункт 2.
- Перед откатом показывается окно подтверждения со списком: «вернётся» / «будет удалён» / «не откатить» (с причиной). Отдельной пометкой — файлы, которые после последней правки агента менял кто-то ещё (пользователь или команда): откат затрёт эти изменения. Кнопки «Откатить» и «Отмена».
- После отката — короткое уведомление в ленте: «Откатили N файлов к сообщению «…»».
- Пока сессия выполняет ход (в любой вкладке), все три пункта неактивны с подсказкой «Дождитесь конца хода».
- Проект не под git → «Откатить код сюда» и пункт 3 неактивны с подсказкой «Откат кода работает только в git-проекте»; ответвление работает.
- Для сообщения, отправленного во время работы агента (вмешательство / в очередь), пункты отката неактивны с подсказкой «Для сообщения, отправленного во время работы, откат недоступен»; ответвление работает, если OmO его допускает.

## 3. Цели

1. Ответвление создаёт отдельный файл сессии и открывает его в новой вкладке; исходная сессия и все вкладки, где она открыта, остаются на своей ветке.
2. Откат возвращает ровно файлы, изменённые инструментами правки агента (`write`, `edit`, `apply_patch`) и его субагентов, к снимку перед выбранным сообщением.
3. Снимок не мешает работе агента и не меняет git-состояние пользователя (индекс, HEAD, ветки, stash, рабочее дерево).
4. Всё переживает перезагрузку окна: точки отката и список правок восстанавливаются из файлов, а не из памяти вкладки.

## 4. Решения (приняты; можно оспорить)

- **Ответвление в новую вкладку**, исходная вкладка не трогается. В OmO команда `fork` переключает живую сессию у **всех** подключённых к ней клиентов (rpc.md, разделы о `new_session`/`switch_session`/`fork` и смене сессии). Поэтому прямой `fork` на хэндле исходной вкладки не годится. Как получить отдельный файл, не сдвинув исходную сессию — проверить первым делом (раздел 7); допустимые пути: отдельный хэндл, `clone` + `navigate_tree` в копии, либо запись нового файла сессии по документированному формату (`session-format.md`) из записей до родителя выбранного сообщения с последующим `open_session {sessionPath}`.
- **Точки отката — только у сообщений, начавших свой ход** (`prompt`). У `steer`/`follow_up` в OmO нет барьера инструментов (rpc.md, «Tool barrier»), поэтому снимок перед ними не гарантирован.
- **Снимок перед каждым `prompt`**: плагин отправляет prompt с `toolBarrier {id, deadlineMs: 35000}` (capability `tool_barrier`), снимает снимок и вызывает `release_tool_barrier`. Читающие инструменты идут сразу, пишущие ждут. Снимок не успел / упал → барьер снимается немедленно, у сообщения нет точки отката (пункты неактивны с подсказкой «Снимок не сохранился»). Работа агента никогда не блокируется дольше дедлайна.
- **Формат снимка**: временный индекс (копия индекса репозитория как затравка, `GIT_INDEX_FILE`), `git add -A` (отслеживаемые и неигнорируемые неотслеживаемые файлы), `write-tree`, `commit-tree` без родителя, ссылка `refs/agent-tabs/checkpoints/<UUID сессии>/<id точки>`. Неотслеживаемые файлы больше 5 МБ в снимок не попадают и записываются как «пропущенные»; правку агента в таком файле откатить нельзя («не откатить: файл больше 5 МБ»). Пользовательские индекс, HEAD, ветки и рабочее дерево не меняются.
- **Список правок агента** берётся из записей сессии (аргументы `write`/`edit`/`apply_patch` после выбранного сообщения в активной ветке) и из журналов субагентов этой сессии, если в них видны те же инструменты. Пути вне репозитория → «не откатить: вне проекта»; игнорируемые git → «не откатить: файл игнорируется git».
- **Пометка «менялся после агента»**: плагин хранит хэш содержимого файла после каждой правки агента (по событию окончания инструмента) в `<agentDir>/agent-tabs/checkpoints/<UUID сессии>.json`. При откате текущий хэш ≠ сохранённого → пометка. Нет записи (расширение не работало в тот момент) → «не проверено».
- **Откат к сообщению N** возвращает все правки агента, сделанные начиная с N (включая ответы на последующие сообщения), к снимку N.
- **Хранение**: ссылки снимков старше 14 дней и ссылки удалённых сессий удаляются при активации расширения. Объекты чистит обычный `git gc`.
- Снимок, откат и уборку выполняет процесс расширения (вне песочницы защиты).

### Уточнения после проверки исполнителем (решения автора)

- **Снимки не принадлежат сессии.** Ссылка: `refs/agent-tabs/checkpoints/<id точки>` (id глобально уникален). Файл `checkpoints/<UUID сессии>.json` перечисляет точки сессии (id точки ↔ `entryId` сообщения) и хэши «после агента». Ответвление копирует в свой файл записи родителя до точки ветвления, ссылки не копируются. Уборка — только по возрасту (14 дней), не по удалению сессии.
- **Пункт 3:** сначала окно подтверждения отката; «Отмена» отменяет и ответвление. После подтверждения — откат, затем ответвление. Откат упал → ответвление не создаётся, ошибка показывается.
- **«Идёт ход»** для отката = любая живая сессия этой среды, у которой корень репозитория совпадает (по списку живых сессий хоста), потому что откат меняет общее рабочее дерево. Для ответвления — только своя сессия. Сессии другой среды не учитываются (известное ограничение).
- **Репозиторий** = `git rev-parse --show-toplevel` от cwd сессии; git worktree — свой корень. Файлы во вложенном репозитории или сабмодуле → «не откатить: другой репозиторий».
- **«Создан агентом»**: файл удаляется, только если его нет в снимке, он не в списке пропущенных и **первое** действие агента с этим путём после точки создавало файл (`write` или добавление файла в `apply_patch`). Если первое действие — `edit`, файл создал кто-то другой → «не откатить: создан не агентом». Пропущенные (больше 5 МБ) → «не откатить».
- **Покинутые ветки** (`/tree`, прежние ответвления): учитываются только правки активной ветки; правки покинутых веток откат не трогает.
- **Вложения** ответвляемого сообщения возвращаются в поле ввода вместе с текстом, если картинки ещё есть у плагина; иначе — только текст.
- **Сообщения не из этого расширения** (CLI, другой клиент) точки отката не имеют: «Снимок не сохранился».

## 5. Не цели

- Откат shell-команд, внешних эффектов (сеть, базы, процессы), файлов вне репозитория и игнорируемых git.
- Откат разговора на месте (в той же вкладке): это ответвление в новую вкладку.
- Защита ссылок снимков от агента под песочницей (агент технически может переписать `refs/agent-tabs/*` git-командой) — известный остаточный риск.
- Проекты без git.

## 6. Анти-цели

- Снимок меняет индекс, ветку, stash или рабочее дерево пользователя, или ссылки снимков уезжают наружу обычным `git push`.
- Ответвление сдвигает исходную вкладку или чужую вкладку той же сессии на новую ветку.
- Откат молча затирает правки пользователя: всё, что может затереть, показано в подтверждении до действия.
- Снимок задерживает агента дольше дедлайна или ломает ход при сбое git.

## 7. Проверить первым делом

- Как получить отдельный файл ответвления, не переключив исходную сессию у подключённых клиентов (варианты из раздела 4); что `fork`/`clone`/`navigate_tree` делают с другими подключениями.
- `tool_barrier` в 5.1.59: `get_protocol_info` объявляет capability; поведение при `steer` во время удержания; что видит лента (`tool_barrier_waiting`).
- Как сопоставить блок сообщения в ленте с `entryId` OmO (`get_fork_messages`, `get_entries`) — в том числе после перезагрузки окна.
- В каком виде инструменты правки субагентов доступны родителю (`omo.task.output` с `mode: "full"`, записи дочерней сессии).
 - Время снимка на большом репозитории с затравкой индекса.

## 8. На усмотрение исполнителя

Структура кода, протокол сообщений панели, вёрстка меню и окна подтверждения (в стиле существующих поповеров и модалок), формат файла `checkpoints/<UUID>.json`, способ сопоставления блока с `entryId`, тексты подсказок сверх заданных.
