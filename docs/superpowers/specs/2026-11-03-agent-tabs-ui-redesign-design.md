# Agent Tabs — редизайн интерфейса в стиле Claude Code

Дата: 2026-11-03. Статус: на утверждение.
 Утверждённый макет: `docs/design/2026-11-03-chat-mockup-v3.html` (открыть в браузере; кнопки над окном переключают состояния).

## 1. Зачем

Плагин работает, но выглядит как черновик: пустой экран, голая строка ввода, выпадающий список модели. Пользователь каждый день работает во вкладках Claude Code и хочет, чтобы вкладки OmO выглядели и вели себя **так же** — «точь-в-точь» по раскладке, плотности и ощущению, — плюс то, что есть только у OmO (субагенты на разных моделях, режимы ulw).

## 2. Цели (что видит пользователь)

1. **Шапка вкладки.** Слева — название сессии; клик по нему превращает его в поле ввода (Enter — сохранить через `set_session_name`, Esc — отмена); новое имя сразу видно в заголовке вкладки редактора и в списке сессий. Справа три иконки: «закрепить», «сессии проекта» (часы), «новая сессия».
2. **Список сессий** — всплывающее окно под часами (заменяет QuickPick): поле «Поиск по сессиям…», строки «название — относительное время» (сейчас / 12 мин / 3 ч / 2 д), текущая сессия выделена синим, у сессии, где агент сейчас работает, — метка «● работает». Наведение показывает ✎ — переименование прямо в списке. Клик — открыть (или сфокусировать уже открытую вкладку). Esc / клик мимо — закрыть.
3. **Лента событий** (как у Claude Code):
   - время сообщения справа над блоком, мелко и серым;
   - сообщение пользователя — в рамке со скруглением; приложенные картинки — превью над текстом;
   - шаги агента — строки с кружком слева и вертикальной линией, соединяющей шаги: зелёный кружок — готово, жёлтый пульсирующий — выполняется, красный — ошибка, серый — служебное;
   - строка инструмента: жирное имя (Read, Edit, Bash…) + моноширинный путь/команда серым; вывод свёрнут, раскрывается по клику; длинный вывод обрезан с «показать всё»;
   - размышления — серая строка «Размышлял N с», раскрывается по клику;
   - шаг субагента — «Задача» + роль моноширинно + метка модели в рамке (например `deep-high` · GPT 6 Astra) + серая подпись «что делает · за сколько»;
   - текст ответа — markdown, `inline code` на тёмном фоне жёлтым;
   - пока агент работает — внизу ленты вращающийся значок и короткий глагол по текущей активности («Думаю…», «Выполняю Bash…», «Жду ответа…»).
4. **Строка ввода** — скруглённый блок внизу по центру: поле (плейсхолдер «Сообщение агенту» / «В очередь ещё сообщение…» во время хода) и панель под ним: «+», «/», пилюля агентов, пилюля модели, справа «Стоп» (белый квадрат, только во время хода). Таймера хода **нет**.
5. **Картинки.** Приложить через «+» (выбор файла), ⌘V, перетаскивание в окно (подсветка «Отпустите, чтобы приложить картинку»). Над полем — миниатюры с ✕. Уходят в OmO вместе с сообщением (`prompt`/`steer`/`follow_up` поле `images`). Клик по любой картинке (миниатюра или в истории) — просмотр на весь экран: ←/→ листать картинки сообщения, Esc — закрыть, ⌘C — копировать.
6. **Окно агентов** — по клику на пилюлю «N агентов работают» (нет агентов — пилюля «0 агентов», окно с пустым состоянием): строки субагентов сессии — статус-кружок, задача, «роль · что делает сейчас», метка модели, длительность. Клик по строке — вывод агента в отдельной вкладке редактора; ⌥-клик — остановить агента.
7. **Окно модели** — по клику на пилюлю модели («Auto · Opus 5.5 xhigh»): «Auto — по ролям: <модель>» сверху, затем группы «Claude» и «GPT» из моделей шлюза, затем «Глубина размышлений» — сегменты из доступных уровней. Подпись «Субагенты всегда идут по ролям из omo.jsonc». Выбор применяется к этой сессии.
8. **Меню «/»** — при вводе `/` в начале поля или по кнопке «/»: строка фильтра и группы «Команды OmO», «Режимы» (`ulw`, `mass ulw` — вставляют ключевое слово), «Навыки» (вставляются как `$имя`), «Шаблоны проекта». Стрелки — выбор, Enter/Tab — вставить, Esc — закрыть. Список живой, из `get_commands`; обновляется по `loaded_surfaces_changed`.

## 3. Не цели

- Код, CSS, иконки или логотип из расширения Claude Code — только собственная реализация в том же стиле; цвета берутся из темы VS Code.
- Переключатель режима правок («Edit automatically») — OmO у нас не спрашивает разрешений; не делаем.
- Таймер хода.
- Вложения, кроме картинок (файлы, PDF).
- Редактор ролей / omo.jsonc.
- Изменения протокола, транспорта и логики сессий из базового дизайна — редизайн только интерфейса и того, что ему нужно от контроллера.

## 4. Анти-цели

- Похоже на Claude Code «издалека», но разваливается в деталях: прыгающая лента при стриминге, скролл, отрывающийся от низа, мигание при обновлении.
- Тормоза на длинной сессии (сотни шагов, большие выводы) или при нескольких картинках.
- Секреты в webview (сохраняется граница редактирования из базового дизайна).
- Картинка, которую нельзя отправить (слишком большая/не тот формат), молча пропадает — пользователь должен видеть причину.

## 5. Решения, принятые в разговоре

- Внешний вид — как во вкладках Claude Code на скриншотах пользователя; макет v3 утверждён («отлично вроде»).
- Картинки в чат — нужны, с просмотром по клику.
- Окно агентов и окно модели — нужны, как в макете.
- Таймер хода — убрать.
- Переименование — клик по названию в шапке.

## 6. Решения автора дизайна (можно оспорить)

- «Закрепить» = закрепить сессию наверху списка сессий этого проекта (хранится локально в состоянии рабочей области VS Code).
- «Auto» в окне модели показывает модель, которую назначил профиль ролей; выбор уровня размышлений тоже по сессии (`set_thinking_level`, список из `get_available_thinking_levels`).
- Ограничения картинок: png/jpeg/gif/webp, до 5 штук на сообщение, до 5 МБ каждая; что не прошло — видимая ошибка у миниатюры.
- Картинки в истории: из записей журнала; если OmO отдаёт заглушку вместо данных — догружаем через `get_media`.
- Вывод агента в отдельной вкладке — `omo.task.output`; остановка — `omo.task.cancel`; длительность — из данных задачи.
- Глагол индикатора выбирается по `session_lifecycle.activity`, без «шуточных» глаголов.
- Список сессий: живой статус «● работает» — из `list_sessions` демона, прошлые — из файлов (как сейчас).

## 6a. Ответы на вопросы ревьюера (факты и решения)

- **Протокол уже всё умеет** (проверено по `~/.omo/binary-runtime/5.1.59/docs/rpc.md`): `images` в `prompt`/`steer`/`follow_up` (стр. ~3685/3780/3811), `get_media` (~4185), `set_thinking_level` / `get_available_thinking_levels` (~4302/4350), `get_commands` (~5287; строки с `source: extension|prompt|skill`, `syntax: slash|dollar`), событие `loaded_surfaces_changed` (~5459), `set_session_name` (~5180). Плейсхолдеры медиа — см. раздел `media_placeholders` (~1052): исполнитель решает, объявлять ли эту возможность; если да — подгрузка через `get_media` с кэшем по id медиа.
 - **Данные субагентов** — из `extension_event omo.task.updated`; вывод — `omo.task.output`, остановка — `omo.task.cancel`. Если модели субагента в данных нет — показываем только роль (без выдумывания модели из omo.jsonc).
- **Auto** — уже реализовано контроллером: `autoModel` = модель, которую профиль ролей назначил главной сессии (`omo-model-profile:applied`); «Auto» = `modelMode: "auto"`; выбор модели = `set_model`; возврат = `set_model(autoModel)`. Группы «Claude»/«GPT» — по провайдеру (`gw-anthropic` → Claude, `gw-openai` → GPT, остальные — «Другие»).
- **Переименование** — новое имя сразу в шапке, в заголовке вкладки редактора и в списке сессий. Для сессии, не открытой ни у кого: временно `open_session {sessionPath}` без `retain_on_disconnect`, `set_session_name`, `close_session`.
- **Закрепление** — по durable id сессии; закрепление исчезнувшей сессии молча отбрасывается.
- **Картинки** — длинная сторона больше 2000 px уменьшается в webview (canvas) до 2000 px (правило Anthropic для запросов с более чем 20 картинками; история пересылает все); исходники больше 20 МБ и не-картинки отклоняются с видимой причиной; до 5 картинок на сообщение. Объём (решение финального ревью): до 5 242 880 символов base64 на картинку и до 12 000 000 на сообщение, чтобы запись журнала оставалась меньше 16 МиБ omo; картинка больше предела сначала пережимается в jpeg (0,85 → 0,7 → 0,55), и только потом — «Картинка слишком большая даже после сжатия»; сверх общего объёма — «Слишком много картинок по объёму для одного сообщения».
- **Меню «/»** — «Команды OmO» = строки `source: extension`, «Шаблоны проекта» = `source: prompt`, «Навыки» = `source: skill` (вставка `$имя`); `ulw` и `mass ulw` — фиксированные пункты, вставляют текст.
- **Тесты** — есть vitest + jsdom для webview (`test/webview/*`), продолжаем их; плюс ручная сверка с макетом.

## 7. На усмотрение исполнителя

Структура кода webview и компонентов, способ рисования (сохранить текущий vanilla TS или перейти на лёгкий фреймворк), иконки (свои SVG), анимации, точные отступы — по макету; как именно хранить закреплённые сессии; оптимизация ленты (виртуализация не обязательна, но ≥ 500 шагов должны листаться плавно).
