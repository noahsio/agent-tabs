# Защита команд агента: классификатор

Защита выключена по умолчанию. Включайте её явно в настройках Agent Tabs после проверки списка защищаемых путей. Белый список публичных IP изначально пуст.

**Решение P45 — спрашиваем только о разрушительном.** Список вопросов — это разрушительные формы плюс то, чем можно отключить саму защиту; всё остальное разрешено по умолчанию. Запреты не тронуты ни одним изменением P45. Сейчас спрашивают, и только они: `rm -rf` по пути из переменной (`rm-rf-variable`), `find … -delete` по домашней папке (`find-delete-home`), разрушительные формы на другом хосте (`REMOTE_CHECKS.escalateIf` через `ssh`: `rm -r` по абсолютному пути или glob, удаления и prune у docker, `DROP`/`TRUNCATE`, `DELETE FROM` без настоящего `WHERE`, `pkill`, `kill -9`), монтирования docker, уносящие папку из песочницы, `hardDeny`-форма на другом хосте (P26), состояние защиты (`guardStateReason`), неизвестный инструмент со словом записи в имени, свои правила `askCustom`. Сняты с вопроса: `git push`, переписывание локальной истории, чтение ключей, глобальные установки, `sudo`, `chmod 777`, `curl` с телом, публичный IP, опасные опции `git`, `mcp-*` с глаголом записи в имени, неизвестный инструмент, повтор команды из истории. Разрушительная форма на другом хосте осталась вопросом именно потому, что песочница Seatbelt до чужой машины не достаёт.

**Решение P44 — наш сбой не является свидетельством о команде.** Решатель не настроен, недоступен, молчит, ответил не по формату; служба не запущена или оборвала соединение — это разрешение со строкой в лог, а не карточка человеку.

`classify(input, rules)` — чистая функция (без fs и сети): возвращает `deny | escalate | allow`, причины, нормализованную команду и ключ (sha256 от нормализованной команды, тел heredoc и cwd). Вход: `{ tool_name, tool_input, cwd, agent_dir?, home? }` (`agent_dir`/`home` нужны только проверке монтирований docker; `home` по умолчанию — домашняя папка).

`commandsOf(tool, input)` — какие команды запускает вызов (живая проверка F7): `bash.command`; `bash_input.input` (`keys` без `input` — не команда; с `enter`/`return` или `submit` — `"replay"`: форма распознаётся, но прочесть, что держит терминал, нельзя, а нечитаемость перестала быть вердиктом (P43/P45) — разрешено; без строкового поля команды — `"invalid"`, запрет); `monitor.command` (кроме `type: path|rpc` и `action: rearm` — это чтение); `eval` — shell из кода (см. ниже); `write|edit|multiedit|apply_patch` → `"write"`; чтение → `"read"`: встроенные OmO 5.1.59 с `writeCapable:false` или `workspaceEffect:"read"` (`read`, `grep`, `find`, `glob`, `ls`, `list`, `todo`, `tool_search`, `look_at`, `lsp_diagnostics|goto_definition|find_references|symbols`, `web_search`, `web_fetch`, `webfetch`, `x_search`), вопросы пользователю `ask_user_question`/`request_user_input`, `bash_output`, `kill_bash`, `bash_resize`, действия ячеек `eval` без кода (`action: list|peek|stop`), вызовы субагентов `task`, `task_*` (вызовы дочерней сессии сами проходят хуки), `memory`, `create_goal|update_goal|get_goal` (решение P29), `team_*`, `thread_*`, `workflow`, `workpool`, `mcp_list_resources`, `mcp_read_resource`, `session_entries`, `lsp_prepare_rename`, `onboarding_*`, `nudge` (P30; эскалация остаётся у `lsp_rename`, `computer*`, `omo_browser_bridge`, `omo_desktop_toolkit`, `show_html_page`; список и источник — `test/kit/fixtures/omo-5.1.59-tools.json`); MCP-инструменты (`mcp_<сервер>_<инструмент>`) — `"mcp"`: разрешены все (P45 — сервер выбирает сам пользователь, а глагол записи в имени не разрушительная форма и не путь к защите; вход MCP-инструмента здесь всё равно никто не читает, так что имя было единственным доводом); любой другой инструмент и `eval`, чей вызов процесса не читается статически → `"unknown-write"`. Сам по себе неизвестный инструмент разрешён (P45), но не-MCP имя со словом write/edit/patch/exec/shell/powershell/bash/eval/run/spawn/monitor (слова по `_`, `-`, `.` и горбам camelCase, `isUnknownWriteTool`: `runCommand`, `fs_write_v2` — да, `truncate`, `prune`, `credit` — нет) — эскалация «неизвестный инструмент записи». Именно эскалация, а не запрет: запрет, который человек не может подтвердить, — ровно та ошибка, что уже была исправлена для argv-формы (P39), и запрещать `fs_write_v2`, разрешая любое другое неизвестное имя, вдобавок несимметрично.

Порядок для каждой «листовой» команды: жёсткий запрет (`hardDeny`) → `--help` пропускается → `allow`-правило (`pattern`; совпал `denyIf` — жёсткий запрет, иначе проверяются только `secrets`, если правило включено вручную, и свои правила «спросить»; `escalateIf` правил `allow` снят вместе с остальным списком вопросов, P45) → эскалация: `builtinEscalate` (кроме снятых `sudo`, `chmod-777`, `curl-write`), `askCustom`, монтирование docker. Снятые группы (`git-push`, `history`, `secrets`, `external-ip`, `global-install`) и снятые встроенные id остаются в формате файла — старый `rules.json` читается и показывается в «Безопасности», — но ничего не сопоставляют.

## Правила v2 (`rules.json`, `default-rules.json`)
`version: 2`; `hardDeny` — globs «всегда запрещено», совпадение со всей командой (как `Bash(…)` у Claude: `rm -rf*`); `groups` — переключатели `git-push`, `history` (reset/rebase/clean/checkout --/restore/branch -D/stash), `secrets`, `external-ip`, `global-install` (шаблоны групп — в `rules.mjs`; все пять сняты решением P45: флаг остаётся частью формата и валидируется, но включённым ничего не спрашивает); `askCustom` — свои правила «спросить»: строка со `*` — glob по всей команде, без `*` — подстрока целыми словами; `allow`, `builtinEscalate` — скрытые от интерфейса правила (regex); `ipWhitelist` — `[{ cidr, note? }]` (частные адреса и loopback разрешены всегда); `decider: { mode: decider-then-me|ask-me|deny, model?: "провайдер/id", timeoutMs }`; `human: { waitSeconds: 60|180|300, card, telegram, telegramChat?, telegramUser? }`. Glob: `*`, `?`, `[…]` (`[!…]`), `\` — буквальный следующий символ.

`loadRules(path)` принимает и v1 (переводит `migrateRules`: группы — по id правил v1; `sudo`, `chmod-777`, `curl-write` и свои правила v1 → `builtinEscalate`; скрытые правила и белый список — из текущих значений по умолчанию плюс адреса v1; `decider.enabled` → режим; ожидание — вверх до 60/180/300). `validateRules(rules)` → `FieldError[]` (`{ field, line?, message }`; `line` — номер элемента списка с 1). `rulesText.mjs`: `parseLines(text, "glob"|"ip")` (строки поля настроек, ошибки с номером строки), `formatIpLines`, `importClaudeDeny` (`Bash(x:*)` → `x*`, `Bash(x)` → `x`, остальное пропускается).

## Что разбирается
`&&`, `||`, `;`, `|`, `&`, переводы строк, `( )`, `$( )`, `<( )`, обратные кавычки, `bash/sh/zsh/fish/su -c`, `eval`, `git -C/-c/--git-dir`.
- **Обёртки** снимаются до сравнения с правилами: `sudo [опции]`, `env [-i] [-u X] [X=…]` (и `env -S 'строка'`), `command` (кроме `command -v`), `builtin`, `exec`, `nice [-n N]`, `timeout [опции] N`, `nohup`, `time`, `stdbuf`, `ionice`, `xargs [опции]`. Правила проверяются по команде целиком, по команде без обёрток и, для `rm -r` и `find … -delete|-exec rm`, по каждой цели отдельно после нормализации (`rm -rf build /` → `rm -rf /`; `find /. -delete`, `find -L // -delete` → `find / -delete`; `//*`, `/./`, `/tmp/../`, `~/./`). У `xargs rm -r` / `xargs find -delete` цели приходят из stdin — эскалация.
- **Heredoc (P25, по умолчанию — исполняется).** Тело — данные, только если одновременно: ограничитель в кавычках (`<<'EOF'`), `<<` и конец строки перед телом — на верхнем уровне (не открыты `$(`, обратные кавычки, `${`, кавычки, подоболочка; исключение — подстановка, в которой ровно `cat <<'EOF' … EOF`: обычная форма сообщения коммита `git commit -m "$(cat <<'EOF' … )"`) и читатель — из списка только-данных: `cat`, `tee`, `git commit -F -`, `grep/rg`, `sed` без команд `e`/`w`, `awk` без `system`/`getline`/`|`, `jq`, `wc`, `sort`, `uniq`, `head`, `tail`, `diff`. Иначе тело — команды (оболочки и неизвестные читатели) или код (интерпретаторы → как `eval`). Here-string — так же. Читатель ищется сквозь `ssh`/`sshpass`, `docker|kubectl exec`.
- **Программа из stdin без известного тела** (`curl … | sh`, `bash -s < file`, `python3 /dev/stdin`), `source <(…)`/`bash <(…)` — эскалация. Интерпретаторы: python, node, bun, deno, ruby, perl, php, osascript, lua, swift. Встроенный код `-c/-e/-r`, собранный оболочкой (`"$(…)"`, `"$VAR"`), — эскалация; литеральный код Python/JS читается как `eval`.
- `$'…'` (ANSI-C) понимают все три разбора — heredoc, разбиение на команды и слова: `\'` не закрывает строку, экранирование раскрывается.
- `docker exec [опции] c <cmd…>` / `kubectl exec … -- <cmd…>`: команда классифицируется в контейнере (катастрофические формы — запрет, `hardDeny` — вопрос); через `ssh` контейнер судится как команда того хоста.
- После `cd`/`pushd` в известную папку (абсолютный путь, `~`, `$HOME`) относительные цели `rm -r`/`find -delete` считаются от неё: `cd / && rm -rf *` → `rm -rf /*`.
- **Команды на другом хосте** — `ssh host '…'` и тело, переданное удалённой оболочке, — проверяются пользовательским `hardDeny` (на другом хосте и в контейнере совпадение — эскалация, не запрет; решение P26) и встроенными `REMOTE_CHECKS` (`rules.mjs`, удалить из `rules.json` нельзя) построчно и целым скриптом, а также обычными эскалациями. `ssh -o ProxyCommand=…|LocalCommand=…|KnownHostsCommand=…` — значение разбирается как локальная команда.
- `REMOTE_CHECKS` (запреты действуют и для тел, переданных в `docker|kubectl exec`; весь список, и запреты и вопросы, сохранён решением P45 — песочница до чужой машины не достаёт): запрет — `rm -rf /`, `mkfs`, `dd … of=/dev/…`, `fdisk`, `find / -delete`, `diskutil erase…`; эскалация — рекурсивный `rm` с любой целью, кроме простого относительного пути (без glob, без `..`), и любой рекурсивный `rm` рядом с `cd`/`pushd`/`popd`/подоболочкой; `docker rm|rmi|… prune|compose down -v`; `DROP`/`TRUNCATE TABLE`; `DELETE FROM` без `WHERE` или с тривиальным условием; `pkill`/`killall`, `kill -9`.
- Переменная, которой в той же команде присвоен литерал, подставляется; если имя присваивалось по-разному, через `$( )`, в `for`/`read` — нет. Значения `GIT_SSH_COMMAND`, `GIT_PAGER`, `GIT_EDITOR`, `GIT_EXTERNAL_DIFF`, `EDITOR`, `PAGER`, `BASH_ENV` и т. п. — и перед командой, и в `export` — разбираются как команды.
- `$(( ))` — арифметика (исполняются только подстановки внутри); `NAME=( … )` — массив.
- `eval` (инструмент): JS/TS — `tool.bash`, `Bun.spawn`, `Bun.$`, `` $`…` ``, `child_process`; Python — `subprocess.*`, `os.system/popen`; `sh|bash|zsh` — код как команда. Нечитаемый вызов процесса, неизвестный язык → эскалация. Константа верхнего уровня, объявленная один раз со статическим значением (строка, шаблон, `String.raw`, цепочка `.replace`/`.replaceAll` с литералами), подставляется: `const` — и как аргумент или элемент массива, если имя нигде не связывается заново (параметр, `catch`, деструктуризация, `for…of`, `eval`/`with`); элемент argv-массива — простое значение (`["git", "-C", repo]`) — неизвестное значение, как `${repo}`. Вызов процесса в функции-помощнике верхнего уровня, которая запускает свои параметры (`const run = async (args) => { … Bun.spawn(args) … }`), судится по каждому её вызову с подставленными аргументами.
- `sudo` снят с вопроса целиком (P45): команда под `sudo`, которая уже совпадает с разрушительным шаблоном, ловится этим шаблоном и так, а сам `sudo` добавлял только прерывания. Правило `allow` `sudo-read` (`pfctl -s…`, `pfctl -t … -T show`, `pfctl -n…`, `launchctl list|print`, `lsof`, `log show`, `dmesg`) осталось в файле, но его `escalateIf` (перенаправление в файл, записывающие флаги `pfctl`) больше не спрашивает.
- `find / … -delete` — запрет, `find ~ … -delete` — эскалация (`find-delete-home`, в списке вопросов осталась). `docker run|create` и `docker compose run` с `-v/--volume/--mount` от `/`, домашней папки или её предка, `~/.omo`, `~/Library/LaunchAgents`, папки агента (`agent_dir`) — эскалация только к человеку (P38: решатель не спрашивается — контейнер работает вне песочницы). Монтирования из `docker-compose.yml`/`compose.yaml` (`docker compose up` читает их из файла) не разбираются — остаточный риск.
- `sshpass -p` к частным адресам не эскалируется; `swift build|test|run --disable-sandbox` и `xcodebuild -IDEPackageSupportDisable…Sandbox=YES` — тоже (F5.1/F5.2).

Кавычечные аргументы с пробелами у «неисполняющих» команд (`echo`, `printf`, `grep`, `rg`, `cat`, `git commit|tag|log|diff|show|grep`, `gh pr|issue create|comment`) не участвуют в сопоставлении, если в сегменте нет `$(`, обратных кавычек и `<<`. Цели перенаправлений (`> "a b/.ssh/key"`) в прозу не входят и проверяются всегда. Слова без пробелов (пути вида `"$HOME/.ssh/id_rsa"`) проверяются всегда. Группа `secrets` снята (P45); если её правило `secrets-access` включить вручную как запись `builtinEscalate`, то из всего, что упоминает `~/.ssh/`, без эскалации проходит только чистое чтение (`cat|grep|head|tail|less`, `ssh -G`, `ssh-keygen -l`, без перенаправления, кроме `/dev/null`) файлов `config`, `known_hosts`, `*.pub`, а `.pem` после обратного слеша не считается путём к ключу: `\.pem` — это синтаксис регулярного выражения или glob. Последнее — исправление ложного срабатывания с карточки, которую сфотографировал человек: `grep -n '^\*\*/\*\.pem$' deploy/.rsyncignore` проверяет, что ключи исключены из деплоя, и был прочитан как доступ к ключу.

## Опасные опции git
Сняты с вопроса решением P45. `git -c alias.*=!…`, `-c core.pager|sshCommand|fsmonitor|editor|hooksPath|askPass=…`, `sequence.editor`, `diff.external`, `credential.helper`, `gpg.program`, `--config-env`, `git grep -O/--open-files-in-pager`, `git log|diff|show --output` — настоящий канал запуска программы, но в корпусе человека он не встретился ни разу, а цена ложного вопроса теперь выше этого риска. Принятый остаточный риск; проверка удалена из `classify.mjs`, тест-свидетель — `the_git_exec_channel_is_retired_by_ruling_and_the_risk_is_recorded_here`.

## Известные пределы статического анализа (остаточный риск, P25)
Защита останавливает ошибки агента; саму защиту бережёт песочница. Известные обходы, которые сознательно не перебираются:
- алиасы и функции оболочки (`alias gp='git push'`, `f() { rm -rf "$1"; }; f /`);
- команды, собранные из частей вне литеральных присваиваний (`git "$sub"`, `${a}${b}`, `printf … | sh` с вычисляемым текстом — последний эскалируется как stdin-программа), IFS/`set --`/массивы как команда, `$'\x72m'`;
- IPv4 в десятичной/шестнадцатеричной форме и IP из частей; имена хостов не проверяются;
- кавычечный путь с пробелами у `cat`/`grep` считается прозой;
- обёртки вне списка (`parallel`, `watch`, `flock`, `script -c`, `chroot`, `doas`, `fakeroot`, `su -l` с нетипичными опциями) и опции обёрток со значением, не перечисленные в списке;
- `cd` в папку из переменной или подстановки (`cd "$X" && rm -rf *`) — цель неизвестна и считается относительной к неизвестной папке (не эскалируется только из-за `cd`); `cd` внутри функций, циклов и `pushd`/`popd`-стеков не отслеживается;
- `xargs` с командой через `sh -c` (`xargs sh -c 'rm -rf "$1"' _`) — внутренний `rm` видит цель `$1` (эскалация `rm-rf-variable`), но не реальную;
- `find` с действием через `-exec sh -c` или `-execdir` с другими программами удаления (`unlink`, `shred`);
- интерпретатор с опциями без `-` (`python3 -W ignore <<PY`) не считается читающим программу из stdin — тело тогда разбирается как команды, а не как код;
- код perl/ruby/php/osascript/lua/swift из stdin проверяется только на «вызывает ли процесс», литеральный `-e` этих языков — только текстовыми правилами;
- `ssh` с нестандартными опциями без значения из `SSH_OPTIONS_WITH_VALUE` и конфиг `~/.ssh/config` (`RemoteCommand`, `ProxyCommand` из файла) не видны;

# Хук (защита v2, тонкий клиент службы)

`hook.mjs --agent-dir <dir>` — хук `PreToolUse` OmO: одна группа в `hooks.json` без `matcher` (ловит все инструменты), `timeout: 330`. JSON на stdin → JSON на stdout, всегда exit 0 (никогда 2). Ответ — `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow|deny","permissionDecisionReason":"[guard] …"}}`; пустой `{}` — пропуск (правила `permission.bash` OmO продолжают действовать). `hook.mjs` — только точка входа: логику (`thinHook.mjs`, `runThinHook`) он загружает динамически внутри `try`, а `uncaughtException`/`unhandledRejection` перехвачены — не загрузился модуль, исключение, отклонённый промис → deny «[guard] ошибка хука защиты: …», exit 0.
- Сначала хук сам читает правила (`guard/rules.json`; нет файла — значения по умолчанию, другая ошибка чтения или невалидный файл — решает служба) и делает ту же проверку «разрешено», что служба: `classify` (с `agent_dir` и `home`) даёт `allow` и команда не трогает состояние защиты (`guardStateReason`); у `write|edit|multiedit|apply_patch` — ни один путь не в защищённых. Тогда `{}` без сокета.
- `bash`/`eval`/`monitor` без строкового `command`/`code` (в том числе `tool_input` строкой), `bash_input` с нестроковым `input` → deny «некорректный вызов инструмента» сразу (служба — так же). `bash_input` только с клавишами — чтение (с `enter`/`return` это «повтор команды из истории»: распознаётся, но разрешён, P45).
- Неизвестный не-MCP инструмент со словом записи или запуска в имени (`isUnknownWriteTool`, см. выше) идёт к службе как эскалация «неизвестный инструмент записи» (P45: больше не deny; имя передаётся службе как есть, чтобы горбы camelCase оставались границами слов). Прочие неизвестные и MCP-инструменты проходят как `{}`, не трогая сокет.
- Остальное — `evaluate` в `guard/hook.sock` (`call.session` = `session_id` из stdin, UUID сессии, F7), при `pending` — `wait` с выданным билетом. Ответ службы `allow`/`deny` — явный `permissionDecision`.
- **Служба не ответила (P44).** Нет сокета, отказ в соединении, соединение дольше 1,5 с, оборванное соединение, ответ не JSON, неполный, `null`, не по протоколу, `{error}`, нет ответа за 320 с от старта хука (ожидание человека — не больше 300 с) — хук не гадает и не ставит вопрос: у него те же правила и тот же классификатор, поэтому он решает сам (`withoutTheService`). Запрет остаётся запретом (с причиной и припиской, что служба не ответила), состояние защиты остаётся запретом, защищённый путь у `write|edit|multiedit|apply_patch` — запретом; всё, что лишь собирались СПРОСИТЬ, проходит как `{}`. Правила, которые не удалось прочитать, заменяются значениями по умолчанию — они строже любой правленой копии. Битый stdin, нет `--agent-dir` → deny «внутренняя ошибка хука». Причина службы не строкой → «служба защиты не указала причину».

`SessionStart` (та же группа, P31): `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"…"}}` — подсказка агенту, что под песочницей `swift build|test|run` нужен `--disable-sandbox`, а xcodebuild — `-IDEPackageSupportDisableManifestSandbox=YES -IDEPackageSupportDisablePackageSandbox=YES` (вложенная песочница запрещена ядром, F5.1–F5.2). Группа есть в `hooks.json`, только пока защита включена.

`install.mjs` (запускается из исходного кита, не из установленной копии): `installGuardFiles(home, source?)` копирует `kit/guard` (или `source` — бандл расширения без `import.meta.url` передаёт свою папку кита) в `~/.omo/kit/<sha256 имён и содержимого, 12 hex>/guard` и возвращает эту папку; `guardFilesDir(home, source?)` — та же папка без записи (её называет окно согласия); `guardHookEntry({ node, kitDir, agentDir })` — группа хука; `guardHandlers({ agentDir, home })` — наши обработчики `{ event, command }` (по ним «Безопасность» проверяет, что node и установленная копия на месте); `guardHookEvents({ agentDir, home })` — события, где она есть; `setGuardHook({ agentDir, home }, on, entry)` — добавляет/убирает нашу группу под `PreToolUse` и `SessionStart` (группы с хуком защиты кита, включая v1 `agent-guard.mjs`: первая заменяется на месте, остальные убираются, чужие обработчики и хуки остаются; выключение без `hooks.json` ничего не пишет) через `writeHooksJson` (единственный писатель `hooks.json`, P4), доверие выдаётся заново всем обработчикам кита (переносится по точной команде, P22).

Сокеты: RPC-сокеты хостов и административные сокеты служб всех сред, `*-main.sock` в user data каждого VS Code, `vscode-(git|ipc)-*.sock` в `$TMPDIR`, общий LSP-демон `~/.omo/lsp-daemon`, `localhost:22`; `(deny lsopen)`, `(deny appleevent-send)`; `/bin/ps` — вне песочницы. Без защиты хост расширения слушает, как и раньше, `<agentDir>/rpc/agent-tabs.sock` (pid — `rpc/agent-tabs.pid`; P35: обновление не бросает и не дублирует работающий хост). Под защитой `rpc/agent-tabs.sock|.pid` всех сред закрыты на запись (и сам `rpc/` от переименования): агент не оставит там поддельный хост на момент выключения защиты; `rpc/` (ключи хоста) создаёт запускающий — расширение и обёртка — до старта, а при выключении расширение удаляет всё, что лежит на `rpc/agent-tabs.sock`, перед запуском хоста там. Защищённый хост слушает `<agentDir>/guard/host/agent-tabs.sock` (каталог закрыт; песочница может только создать и `chmod` этот сокет — OmO 5.1.59 делает оба, проверено живьём; удалить, переместить или подключиться — нет). Обойтись без разрешения на создание нельзя: сокет создаёт сам OmO, передать ему готовый дескриптор нечем. Поэтому создать сокет может любой процесс в песочнице, и расширение доверяет ему (N6), только если `guard/host/agent-tabs.pid` (его пишет лишь расширение) называет живой процесс с командой `… --mode rpc --listen unix://<этот сокет>`, и этот процесс держит сокет (`lsof`); иначе чужой процесс не трогается, сокет отвязывается от пути, запускается свой хост, а после старта своего хоста снова проверяется, что сокет держит именно он; там же pid-файл (пишется заново, `wx` после удаления: ссылка не перенаправит запись); мёртвый сокет расширение удаляет перед запуском. `lspDaemonDir(agentDir)` = `<agentDir>/lsp-daemon` (если сокет демона длиннее 100 байт — `<agentDir>/lsp`): защищённый хост получает `OMO_LSP_DAEMON_DIR` (F5.3).

Хост расширения (`src/daemon.ts`) и обёртка `omo-<env>` при наличии профиля запускают `omo` через `/usr/bin/sandbox-exec -f <профиль>` с `OMO_LSP_DAEMON_DIR`. Профиль пересоздаётся при активации расширения и перед каждым запуском хоста (P7). Включение и выключение — `src/guard/protection.ts` (`enableProtection`, `disableProtection` — оба перезапускают хост: «Перезапустить» останавливает хост расширения на обоих местах и запускает новый там, где велит защита; `protectionState`: off/on/broken, «on» — ещё и служба отвечает на хуковом сокете; служба не поднялась за 10 с — LaunchAgent убирается, состояние off), LaunchAgent службы — `src/guard/launchAgent.ts` (`local.agent-tabs.guard.<8 hex sha256(agentDir)>`; node — тот, что человек не может переписать, иначе его префикс закрыт по P33); кит-часть для расширения — `lifecycle.mjs`.

Решает не `kit/guard` расширения, а установленная копия, поэтому обновление расширения само по себе до человека не доходит: `refreshProtection` (там же) при каждой активации окна сверяет установленное с нынешним китом — группа хука под оба события и plist LaunchAgent должны быть ровно тем, что записал бы `provision` для `guardFilesDir(home, kit/guard)` и для того node, который хук уже называет. Сверка — только чтение файлов (ни `launchctl`, ни login-оболочки), поэтому активация, которой нечего делать, не делает ничего. Расходится — то же `provision`: правила → копия кита → plist → перезагрузка службы → группа хука → профиль; node и закрытые на запись папки (`guard/sandbox.json`) не пересчитываются — человек согласился на них при включении, — и хост не перезапускается: профиль не менялся, прерывать ход незачем. Одно обновление на все окна: сокет-lock `guard/refresh.sock` (тот же приём, что у запуска хоста в `src/daemon.ts`), проигравшее окно оставляет работу держателю, а сверка повторяется уже под lock. Сбой не оставляет пару рассогласованной: plist для копии, которую называет `hooks.json`, возвращается и загружается заново (старая копия на месте — установка новой никогда не удаляет прежнюю), а причина уходит в «Безопасность». Какая копия работает и когда она установлена, видно там же (`installedKit`): «старее установленного расширения» — значит решают её правила, а не нынешние.

**Не цели / остаточный риск песочницы** (P36: песочница защищает саму защиту и закрывает побеги без участия человека; список «всего, что человек когда-нибудь выполнит» перечислить нельзя):
- сокеты субагентов OmO в `<agentDir>/rpc/` — их ключи хост обязан читать (спецификация §4, «Не цели»);
- сокет Docker открыт осознанно: контейнер с монтированием домашнего каталога обходит любые запреты на запись (решение ledger, F5);
- сеть и чтение не ограничиваются;
- отложенный запуск, который требует действия человека: `.vscode/tasks.json` с `runOn: folderOpen` (VS Code спрашивает доверие к папке), голые репозитории в подкаталогах проекта (`*.git/config` с `core.fsmonitor` — сработает, если человек сам запустит там git), `include`/`includeIf` в незакрытых конфигурациях, rc-файлы, подключённые через переменную в пути (`$ZSH/oh-my-zsh.sh`), и прочие способы попасть в автозапуск, которых нет в списке выше;
- ссылка из PATH на файл в обычном каталоге домашнего (`~/Documents/…`), в git-репозитории или в рабочей области (P38): закрыт только сам файл, не то, что он загружает, и не его каталог.

Самозащита (служба, `protect.mjs`):
- write/edit/apply_patch в `<agentDir>/guard/**`, `<agentDir>/hooks.json`, `<agentDir>/hooks-state.json`, `~/.omo/kit/**`, `~/.omo/omo.jsonc` — жёсткий запрет (путь от cwd, `~` раскрывается, симлинки разрешаются по ближайшему существующему родителю; на macOS без учёта регистра).
- bash/eval (и вход любого другого инструмента) — только человек, без решателя и кэша, если упоминает `agent-guard` или `guardctl`, путь к файлу состояния решателя (компонент `guard/` и `rules|cache|answers|used|watchers|pending|sandbox.json`, `sandbox.sb`, `service.lock`, `*.sock`), папку `guard/` или `keys/` папки агента любого окружения (`~/.omo/agent` и папка второй среды, если она задана), путь в agentDir или `~/.omo/kit` (абсолютный, `~/`, `$HOME/`; литералы, склеенные `+` или разделённые запятыми, как в `path.join`, читаются одним путём), `hooks(-state).json`, или запущен из agentDir/кита. Решают пути, а не слова: проза о решателе («guard», «cache», «rules» в спецификации, которую код пишет в файл проекта) — не его состояние.
- Предел: путь, собранный в коде по частям (`["gu","ard"].join("")`), статически не виден — это защита от ошибок агента, не песочница.

Telegram (`human.telegram: true`): токен бота среды — `<agentDir>/keys/telegram.key` (0600, папка закрыта песочницей для записи), чат и необязательный пользователь — `human.telegramChat`/`human.telegramUser` в правилах (числовые id; задаются в «Безопасности»: «Найти чат» берёт последний личный чат, написавший боту). Без файла ключа — по-старому бот и чат из `tg.env` супервизора (`--tg-env` службы, по умолчанию `~/.claude/skills/supervisor/tg.env`; необязательный `TG_USER_ID`); служба перечитывает ключ и правила при каждой отправке; кнопки `ag:a|d:<id>`, нажатия принимаются только из настроенного чата (и от настроенного пользователя). Текст команды уходит третьей стороне (Telegram). Не запускайте одновременно `daemon.py` супервизора с тем же ботом: он может первым подтвердить наши нажатия — ответ потеряется (ожидание закончится deny по таймауту).

# Служба решений (защита v2)

`service.mjs --agent-dir <dir> [--omo <путь>] [--tg-env <tg.env>]` — фоновый процесс на среду, вне песочницы. Владеет правилами (`guard/rules.json`, единственный писатель; нет файла — значения по умолчанию; невалидный файл — всё запрещается, `status.rulesOk: false`), кэшем решателя (`guard/cache.json`, 24 ч, только allow/deny решателя), открытыми запросами и ответами (в памяти), Telegram. Протокол — в шапке `service.mjs`.
- **Хуковый сокет** `guard/hook.sock` (доступен из песочницы): `evaluate` и `wait`, одна строка JSON в каждую сторону; всё остальное — `{"error":"unknown op"}`. `evaluate` со спорным вызовом отдаёт `{decision:"pending", id, ticket}`; `wait` требует `ticket` своего вызова (чужой или пустой → `{error}`, разрешение не тратится; общий запрос — у каждого вызова свой билет и свой инструмент). Служба классифицирует вызов заново (`agent_dir`, `home` передаются в `classify`), уровню от хука не верит.
- **Административный сокет** `guard/admin.sock` (песочница не подключится): `pending`, `answer` (`allow-once|deny`, `by: agent-tabs|cli|telegram`, первый ответ выигрывает), `rules.get`, `rules.set` (`validateRules` → `FieldError[]`, при ошибке файл не меняется), `status`, `subscribe` (сначала `{ok:true}` и открытые запросы как `pending`, затем события `pending`/`resolved`; окончательный вердикт решателя — `resolved` с `by:"decider"`, `decider` и `item`).
- Режимы: `decider-then-me` — окончательно только allow решателя (кэш 24 ч); его deny и его собственный обдуманный ask → человек, с вердиктом решателя на карточке (deny из старого кэша — тоже к человеку); жёсткие запреты правил от решателя не зависят; `ask-me` → человек; `deny` → «спорная команда запрещена настройками защиты». Человек не ответил за `human.waitSeconds` → deny; служба остановлена посреди ожидания человека → deny.
- **Сбой решателя (P44) — разрешение со строкой в лог, а не карточка.** Модель не выбрана (`decider.model` — `""` по умолчанию), нет транспорта к ней, решатель не настроен, недоступен (сеть, HTTP, `omo` не запустился или вышел с кодом), не ответил за `timeoutMs`, ответил не по формату, служба остановилась посреди решения — всё это сбои наши, а не свидетельство о команде: `allow` и строка `[guard …] decider-failed session=… tool=… reason=…` в stderr (её забирает LaunchAgent, `src/guard/launchAgent.ts`). Команда, совпавшая с запретом, сюда не доходит (запрет отвечает раньше), а вызов, трогающий состояние защиты, решателя не спрашивает вовсе — так что ничто из этого не разрешает то, о чём был настоящий вердикт. «Разрешить один раз» — ровно этот вызов, плюс в течение 60 с парный `bash` того же `eval` и той же сессии (`call.session` — UUID сессии, F7).
- Решатель (`resolveDeciderTransport`): HTTP — адрес и протокол (`anthropic-messages`, `openai-responses`, `openai-completions`) из `models.json` (или встроенные `anthropic`/`openai`), ключ — из файла `apiKey: "!cat '<путь>'"` (разбирается, оболочка не запускается) или `api_key` в `auth.json`; провайдер только с входом через аккаунт → `omo -p … --no-tools --no-session …` (F8) с `OMO_CODING_AGENT_DIR`. Ошибки решателя ключа не содержат.
- Пределы того, что достижимо из песочницы: открытых запросов ≤ 10 на сессию и ≤ 50 всего (сверх — deny «слишком много ожидающих решений»; предел на сессию — лишь подсказка, id сессии присылает сам вызывающий, настоящая граница — общий предел); билетов на один запрос ≤ 16; решатель — ≤ 2 вызова одновременно, ≤ 8 в очереди (сверх — к человеку), одинаковые вызовы (ключ) ждут один ответ; Telegram — не чаще раза в 2 с, повтор того же ключа не отправляется; строка запроса должна прийти за 5 с от подключения, сколько бы байтов ни капало (ожидание `wait` — без срока), соединений ≤ 64, строка ≤ 1 МБ. Ошибка обработчика административного сокета — ответ `{ok:false, error}`, а не падение.
- Один экземпляр на среду (P28): `guard/service.lock` создаётся `link()` из временного файла `{pid, startedAt, token}` до сокетов. Lock моложе 10 с — служба запускается (отказ); старше — занят, только пока его хуковый сокет принимает соединения (живой pid сам по себе ничего не значит: после перезагрузки его может носить другой процесс); иначе он отодвигается в сторону (если это всё ещё тот же файл) и `link()` повторяется. Известные ключи перечитываются не чаще раза в 30 с. `omo -p` решателя — в своей группе процессов, по таймауту убивается вся группа.
- Сокеты 0600 в папке 0700; путь длиннее 103 байт — служба не стартует и называет путь; оставшийся файл сокета удаляется при старте, живой — «служба защиты уже запущена». Команда в карточке — без известных ключей (`‹redacted›`: ключ решателя, `keys/`, `auth.json`, ключи `models.json` включая `$ENV`, токены в `<провайдер>-accounts/`, токен Telegram), не длиннее 4096 символов; у `eval` команда в карточке — извлечённые shell-команды по строке, а сам код — отдельное поле `code` (так же без ключей и не длиннее 4096; в чате — свёрнутый блок «Код eval», в `guardctl` — после команды, решатель получает их раздельно; ключ кэша и проверка состояния решателя — по всему коду) (B2); каждая причина — не длиннее 300.

**Остаточный риск lock-файла.** Единственность службы в итоге обеспечивает launchd (одна метка LaunchAgent на среду); `service.lock` — вторая линия защиты, и у него известные узкие места:
- окно переименования при трёх одновременных стартах: стартующий, чьё переименование унесло не тот lock, который он признал устаревшим (его уже успел поставить второй), возвращает его через `link()` и отступает; если за это время место занял третий, lock второго теряется, и второй работает без своего lock-файла;
- проба сокета считает живую службу с переполненной очередью `listen` мёртвой (connect получает отказ) — её lock будет заменён;
- mtime lock-файла из будущего (переведённые часы) продлевает «запускается» дольше 10 с;
- после падения посреди захвата могут остаться `service.lock.*.tmp` и `service.lock.stale.*` — служба их не убирает (они ни на что не влияют).

`guardctl.mjs [--agent-dir <dir>] pending | allow <id> | deny <id>` — ответ из терминала через административный сокет; `allow`/`deny` требуют ввести «да» на `/dev/tty` (`tty.mjs`). Клиенты берут пути из `sockets.mjs` и службу не загружают.
